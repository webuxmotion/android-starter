# Урок 1. Екран, текст і `Modifier`

**Мета:** зрозуміти, з чого складається екран у Compose, і навчитися керувати
розміром, відступами та стилем через `Modifier`.

**Стартова точка:** проєкт після початкового коміту — один `Text` по центру
темного екрана.

## Що таке `@Composable`

```kotlin
@Composable
fun HelloScreen() { … }
```

Це звичайна функція Kotlin з анотацією `@Composable`. Вона нічого не повертає —
вона **описує**, що має бути на екрані. Compose викликає її, будує з неї дерево
елементів і малює. Коли дані змінюються, Compose викликає функцію ще раз і
перемальовує лише те, що справді змінилось. Цей повторний виклик називається
**рекомпозиція**, детально — в уроці 3.

Правила, які варто прийняти одразу:

- `@Composable`-функцію можна викликати тільки з іншої `@Composable`-функції.
- Назва пишеться з великої літери (`HelloScreen`, не `helloScreen`) — це
  домовленість спільноти, яка відрізняє «елемент UI» від звичайної функції.
- Функція має бути безсторонньою: жодних мережевих запитів чи запису у файл
  прямо в тілі. Вона може викликатись багато разів на секунду.

## Що таке `Modifier`

`Modifier` — ланцюжок налаштувань, який передається елементу і описує все
навколо його вмісту: розмір, відступи, фон, рамку, реакцію на дотик.

```kotlin
Modifier
    .fillMaxSize()      // зайняти весь доступний простір
    .padding(24.dp)     // відступ 24 незалежних пікселі з усіх боків
```

`dp` (density-independent pixels) — одиниця, незалежна від щільності екрана.
24.dp виглядають однаково на дешевому Redmi і на флагмані з 4K-екраном. Для
розмірів шрифту є окрема одиниця `sp`, яка ще й враховує налаштування розміру
шрифту в системі.

**Порядок у ланцюжку має значення** — модифікатори застосовуються зліва направо:

```kotlin
Modifier.padding(16.dp).background(Color.Red)   // відступ ЗЗОВНІ червоного прямокутника
Modifier.background(Color.Red).padding(16.dp)   // червоний прямокутник, відступ ВСЕРЕДИНІ
```

Це найчастіше джерело «чому воно виглядає не так» у новачків.

## Крок 1. Додати відступи й стиль тексту

Зараз довгий текст упирається в краї екрана. Виправимо це і заразом зробимо
текст помітнішим.

Відкрий `…/androidstarter/MainActivity.kt` і заміни функцію `HelloScreen` на:

```kotlin
@Composable
fun HelloScreen() {
    Box(
        modifier = Modifier
            .fillMaxSize()
            .padding(24.dp),
        contentAlignment = Alignment.Center,
    ) {
        Text(
            text = "Привіт, Android!",
            style = MaterialTheme.typography.headlineMedium,
            textAlign = TextAlign.Center,
        )
    }
}
```

Додай угорі файлу відсутні імпорти:

```kotlin
import androidx.compose.foundation.layout.padding
import androidx.compose.ui.text.style.TextAlign
import androidx.compose.ui.unit.dp
```

`MaterialTheme` вже імпортований. `Box` — найпростіший контейнер: він кладе
вміст поверх себе, а `contentAlignment` каже, де саме його розмістити.

## Крок 2. Подивитись, що дає `style`

`MaterialTheme.typography` — набір готових стилів тексту з Material Design.
Спробуй по черзі й обери, що подобається:

| Стиль | Приблизний розмір | Для чого |
|---|---|---|
| `displayLarge` | 57sp | великі цифри, годинник |
| `headlineMedium` | 28sp | заголовок екрана |
| `titleMedium` | 16sp | заголовок картки |
| `bodyLarge` | 16sp | основний текст |
| `labelSmall` | 11sp | підписи, дрібні позначки |

Готові стилі кращі за ручний `fontSize = 28.sp`: коли в уроці 4 з'явиться своя
тема, увесь текст застосунку зміниться узгоджено, з одного місця.

Окремі властивості можна перевизначати поверх стилю:

```kotlin
Text(
    text = "Привіт, Android!",
    style = MaterialTheme.typography.headlineMedium,
    fontWeight = FontWeight.Bold,      // import androidx.compose.ui.text.font.FontWeight
)
```

## Що змінилось у git

```
app/src/main/java/com/webuxmotion/androidstarter/MainActivity.kt
```

**Один файл.** Запам'ятай це відчуття: зміни всередині UI не зачіпають ні
збірку, ні маніфест, ні ресурси. У наступних уроках список файлів у коміті
почне рости — і кожен новий файл матиме зрозумілу причину.

## Вправа

1. Постав `padding` **перед** `fillMaxSize()` і подивись, що зміниться (нічого
   помітного — чому?). Потім спробуй `Modifier.padding(24.dp).fillMaxSize()`
   всередині ще одного `Box` із фоном.
2. Зроби текст вирівняним не по центру екрана, а зверху: `Alignment.TopCenter`.
3. Додай другий `Text` у той самий `Box` і поясни собі, чому вони наклались
   один на одного. Рішення — в уроці 2.
